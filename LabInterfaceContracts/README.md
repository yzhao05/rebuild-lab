# Lab Interface Contracts

This folder is the contract source of truth for the Summer26 lab workflow.

The lab1 files were copied from:

`Assets/Labs/Electrostatics/Config/lab1_electrostatics_*.example.json`

The files here define example interfaces for the existing Summer26 scene sequence:

- `lab1_electrostatics`: `Assets/Scenes/Static_Electric_Field.unity`
- `lab2_static_magnetic_field`: `Assets/Scenes/Static_Magnetic_Field.unity`
- `lab3_wave_polarization`: `Assets/Scenes/Wave_Polarization.unity`

Files ending in `.example.json` are legacy examples. New rebuilds and labs use
canonical `.json` files generated by `tools/labflow/labflow.py new`. Each lab
must have exactly these five kinds:

- `lab_spec`
- `objects`
- `steps`
- `rubric`
- `telemetry_map`

Run `python tools/labflow/labflow.py validate --lab-id <lab_id>` before design
approval or C# scaffolding. The validator checks parsing, shared `lab_id`,
unique IDs, step/object references, rubric/step references, and baseline
telemetry events. The Lab MCP server prefers canonical files and falls back to
the legacy examples.
